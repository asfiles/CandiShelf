# CandiShelf

[English](README.md) · **Русский**

**Приватный поиск кандидатов на локальном AI. Без аккаунтов, API-ключей и облачной обработки.**

Локальное приложение для работы с коллекцией резюме — офлайн, для независимых
HR-специалистов и небольших компаний.

CandiShelf загружает коллекцию резюме, извлекает данные о кандидатах, создаёт
локальную базу, позволяет искать кандидатов и сопоставлять их с вакансией —
**полностью на вашем компьютере**. Ни одно резюме не отправляется во внешние
сервисы. Ничего не нужно настраивать вручную: при первом запуске CandiShelf
автоматически скачивает и проверяет локальную AI-модель, а дальше всё работает
офлайн.

**Руководство пользователя:** [English](manual/README.md) · [Русский](manual/README.ru.md)

> CandiShelf — это «полка кандидатов», а не полноценная ATS. Приложение даёт
> рекомендации для HR-специалиста, но никогда не отклоняет и не принимает
> кандидатов автоматически.

## Функционал

**Импорт**
- Загрузка резюме в форматах PDF, DOCX и TXT: выбор файлов, выбор папки или
  перетаскивание в окно.
- Прогресс обработки, счётчик документов и список ошибок по файлам — ошибка
  одного документа не останавливает обработку остальных. Есть опция копирования
  оригиналов в хранилище приложения.

**Карточка кандидата**
- Имя, email, телефон, LinkedIn, местоположение, последняя должность, опыт,
  навыки, языки, образование и история работы.
- Полный извлечённый текст и исходный файл; открытие оригинала в один клик.
- Редактирование любого поля, повторная обработка резюме, удаление кандидата.

**Поиск**
- Семантический поиск естественным языком на локальной модели эмбеддингов —
  опишите, кого ищете (например, «DevOps-инженер с опытом в финтехе»), и
  кандидаты ранжируются по смыслу, а не по совпадению слов.
- Точный поиск по структурированным данным: введите полный e-mail, телефон или
  ссылку на LinkedIn, чтобы перейти сразу к нужному человеку, либо ФИО — слова
  могут идти в любом порядке. Такие совпадения приоритетнее смысловых.
- Фильтры: местоположение, диапазон опыта (минимум и максимум), обязательные и
  исключаемые навыки, языки, последняя должность, а также «только шортлист» и
  «скрыть дубликаты».
- В каждом результате видно, *как* он совпал (точный e-mail / телефон /
  LinkedIn, ФИО или смысловое совпадение), и фрагмент из резюме.

**Сопоставление с вакансией**
- Вставьте текст вакансии: приложение выделяет требования, ранжирует кандидатов и
  показывает совпавшие и не найденные требования с подтверждающими фрагментами.

**Дубли и shortlist**
- Резюме одного человека определяются по совпадению email / телефона / LinkedIn.
- Добавление в shortlist и экспорт в CSV.

**База данных и настройки**
- Удаление кандидата, полная очистка базы, перенос хранилища в другую папку.
- Управление AI-моделями, каталог данных, проверка обновлений.
- **Язык интерфейса** — русский и английский. Интерфейс автоматически следует
  локали ОС (российская локаль → русский, иначе английский), а переключить язык
  можно одним кликом в настройках; выбор сохраняется.
- Экран **«О программе»** с версией, автором и лицензией.

**Приватность и безопасность**
- Всё работает локально: нет телеметрии и нет обращений к сети после
  необязательной загрузки модели. Входные файлы только *читаются как текст* —
  никогда не исполняются и не отображаются; текст очищается, SQL полностью
  параметризован, ZIP-части DOCX ограничены по размеру (защита от zip-бомб),
  загрузки проверяются по контрольной сумме.

## Архитектура

| Слой       | Технологии                                                      |
| ---------- | -------------------------------------------------------------- |
| Оболочка   | [Tauri 2](https://tauri.app) (Rust)                            |
| Интерфейс  | React 18 + TypeScript + Vite                                   |
| База       | SQLite (встроенный) — кандидаты и эмбеддинги                   |
| AI-движок  | Локальные эмбеддинги через [candle](https://github.com/huggingface/candle) (чистый Rust; sentence-transformers MiniLM). Модели скачиваются при первом запуске, с проверкой контрольной суммы |
| CI/CD      | GitHub Actions (нативные раннеры Windows/macOS)                |

```
src/                     фронтенд на React + TypeScript
  screens/               Главный экран, Импорт, Вакансия, Настройки, О программе, первый запуск
  components/            Переиспользуемый UI (иконки, модальные окна, тосты, строка кандидата)
  lib/                   Мост к API, типы, mock-бэкенд, форматирование
src-tauri/               бэкенд на Rust
  src/extract/           Извлечение текста PDF / DOCX / TXT + санитизация
  src/ai/                Эмбеддинги (candle) + загрузка и проверка моделей
  src/db.rs              SQLite: кандидаты и определение дублей
  src/parser.rs          Эвристическое извлечение полей
  src/filters.rs         Общие структурные фильтры (список и поиск)
  src/search.rs          Гибридный поиск + подбор под вакансию
  src/importer.rs        Пайплайн импорта (обход файлов, изоляция ошибок)
  src/export.rs          Экспорт shortlist в CSV
  src/commands.rs        Обработчики IPC-команд Tauri
.github/workflows/       CI (тесты + проверочная сборка) и Release
```

## Хранение данных

Пользовательские данные хранятся отдельно от исполняемого файла, по правилам
платформы:

```
Windows: %LOCALAPPDATA%\CandiShelf\
macOS:   ~/Library/Application Support/CandiShelf/
```

Там находятся локальная база и эмбеддинги, загруженные модели,
настройки и (опционально) скопированные оригиналы резюме. Логи не содержат
содержимого резюме. Каталог можно изменить в настройках.

## Разработка

Требования: [Node.js 20.19+](https://nodejs.org),
[Rust toolchain](https://rustup.rs) и
[системные зависимости Tauri 2](https://v2.tauri.app/start/prerequisites/) для
вашей ОС (в Debian/Ubuntu: `libwebkit2gtk-4.1-dev`, `libgtk-3-dev`,
`librsvg2-dev`, `patchelf`, `libappindicator3-dev`).

```bash
npm install          # установка зависимостей фронтенда

npm run dev          # интерфейс в браузере (использует встроенный mock-бэкенд)
npm run tauri dev    # полноценное desktop-приложение (реальный бэкенд на Rust)

# Проверки качества
npm run lint
npm run typecheck
npm test                       # unit-тесты фронтенда (Vitest)
cargo test --manifest-path src-tauri/Cargo.toml   # тесты Rust
```

> `npm run dev` открывает приложение в обычном браузере. Так как там нет Runtime
> Tauri, приложение прозрачно переключается на **встроенный mock-бэкенд**, чтобы
> весь интерфейс можно было изучить без сборки Rust. Для реального постоянного
> бэкенда используйте `npm run tauri dev`.

### Перегенерация иконок

```bash
python3 scripts/gen_icons.py   # пишет src-tauri/icons/* и public/icon.png
```

### Защита от supply-chain атак (npm)

Путь установки зависимостей защищён от npm supply-chain атак:

- **`ignore-scripts=true`** (`.npmrc`) — install/lifecycle-скрипты зависимостей
  не запускаются при `npm install`. Это блокирует самый частый вектор: исполнение
  кода через `postinstall` вредоносного или скомпрометированного пакета.
  Скрипты проекта (`npm run dev|build|test|tauri`) работают как обычно. Если
  зависимости действительно нужен её build-шаг, разрешите его явно через
  `npm rebuild <pkg>`.
- **Точные версии** — `save-exact=true` и точные версии в `package.json`; CI
  падает при появлении «плавающих» диапазонов (`^`, `~`, `*`, `latest`).
- **Аудит зависимостей** — отдельная джоба CI запускает
  `npm audit --audit-level=high` и падает на high/critical.
- **Минимальные права CI** — workflow'ы работают с `contents: read`.
- **Dependabot** — еженедельные ревьюируемые PR для npm, Cargo и GitHub Actions.

> Рекомендация на будущее: закрепить GitHub Actions на полные commit-SHA (сейчас
> закреплены по мажорным тегам), чтобы перенос тега не влиял на сборку.

### Версионирование (тэг ↔ приложение)

Версия в приложении (в сайдбаре и на экране **«О программе»**) всегда совпадает с
Git-тэгом. Release-workflow перед сборкой выполняет `npm run set-version <tag>`,
синхронизируя `package.json`, `src-tauri/tauri.conf.json` и
`src-tauri/Cargo.toml`, поэтому сборка из тэга `v0.1.0` показывает `v0.1.0`
(`0.1.0` из Cargo). Описание каждого релиза формируется из
[CHANGELOG.md](CHANGELOG.md).

## AI-модели

Поиск и сопоставление с вакансией **полностью работают на локальной языковой
модели**. Чтобы portable-файл не занимал гигабайты, модели **не** входят в
сборку: при первом запуске вы выбираете одну и скачиваете её один раз. Дальше
всё работает офлайн, и ни одно резюме не покидает устройство.

| Модель | Языки | Размер | Примечание |
| --- | --- | --- | --- |
| `minilm-l6-en` (all-MiniLM-L6-v2) | английский | 87 МБ | Компактная и быстрая; для англоязычных резюме |
| `multilingual-l12` (paraphrase-multilingual-MiniLM-L12-v2) | 50+, вкл. русский | 458 МБ | Крупнее и медленнее; для не-английских резюме |

Обе дают 384-мерные эмбеддинги и работают на CPU через
[candle](https://github.com/huggingface/candle). Загрузку можно проверять по
контрольной сумме (закреплённый SHA-256 в `ai/mod.rs`). В разделе
**Настройки → AI-модели** можно сменить или перекачать активную модель; так как
разные модели живут в разных пространствах эмбеддингов, при смене модели
существующие кандидаты автоматически переиндексируются (с прогрессом), чтобы
поиск оставался согласованным.

### Установка модели вручную (без скачивания)

Скачивание необязательно. CandiShelf только **читает** файлы модели с диска — их
загрузка это единственный выход приложения в сеть. На машине без интернета
скачайте файлы на другом устройстве любым способом (браузер, `curl`, `wget`) и
положите их в папку модели внутри каталога данных (см.
[Хранение данных](#хранение-данных)):

```
<каталог данных>/models/minilm-l6-en/       # английская модель
<каталог данных>/models/multilingual-l12/   # многоязычная модель
```

В каждой папке должно лежать ровно три файла — имена одинаковы для обеих моделей:

| Файл | Назначение |
| --- | --- |
| `model.safetensors` | веса модели |
| `tokenizer.json` | токенизатор |
| `config.json` | конфигурация модели |

**Английская — `all-MiniLM-L6-v2`** → в `<каталог данных>/models/minilm-l6-en/`:

- <https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/resolve/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/model.safetensors>
- <https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/resolve/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/tokenizer.json>
- <https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/resolve/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/config.json>

**Многоязычная — `paraphrase-multilingual-MiniLM-L12-v2`** → в
`<каталог данных>/models/multilingual-l12/`:

- <https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2/resolve/e8f8c211226b894fcb81acc59f3b34ba3efd5f42/model.safetensors>
- <https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2/resolve/e8f8c211226b894fcb81acc59f3b34ba3efd5f42/tokenizer.json>
- <https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2/resolve/e8f8c211226b894fcb81acc59f3b34ba3efd5f42/config.json>

Например, английская модель одной командой:

```bash
BASE=https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2/resolve/1110a243fdf4706b3f48f1d95db1a4f5529b4d41
DEST="${XDG_DATA_HOME:-$HOME/.local/share}/CandiShelf/models/minilm-l6-en"
mkdir -p "$DEST"
for f in model.safetensors tokenizer.json config.json; do
  curl -L "$BASE/$f" -o "$DEST/$f"
done
```

Как только файлы на месте, CandiShelf распознаёт модель (помечается как
**Установлена**) и активирует её, ничего не скачивая. Точная папка и список файлов
для каждой модели показаны на экране первого запуска и в разделе
**Настройки → AI-модели**.

> Regex-бэкенд токенизатора (`onig`) — это C-зависимость только на этапе сборки
> (исходники в комплекте, статическая линковка). В отличие от ONNX Runtime, нет
> runtime-библиотеки, которую надо поставлять и подписывать, поэтому кросс-
> платформенная упаковка остаётся простой.

## Сборка portable-релизов

Нативные артефакты без установщика собираются в GitHub Actions на
соответствующих раннерах. Пуш тэга вида `v0.1.0` собирает и публикует
GitHub Release:

```
candishelf-Windows-x64.exe
candishelf-macOS-Universal.zip
SHA256SUMS.txt
```

Сборка для Windows — один portable `.exe`, без установщика. Сборка для macOS —
один **universal** `.zip` (Intel + Apple Silicon), который распаковывается сразу
в `CandiShelf.app`: распакуйте и откройте приложение.

- **PR** — тесты и проверочная сборка на Windows и macOS.
- **Merge в `main`** — тестовая сборка.
- **Тэги `v*.*.*`** — production-релиз с portable-файлами и контрольными суммами.

Сборки для macOS и Windows не подписаны, поэтому при первом запуске возможны
предупреждения Gatekeeper (macOS) и SmartScreen (Windows). macOS-приложение
подписано ad-hoc, но **не нотаризовано**, поэтому при первом запуске macOS может
сообщить, что **«CandiShelf повреждено и не может быть открыто»** — это проверка
карантина Gatekeeper для скачанных файлов, а не битый архив. Учтите, что на
macOS 15 (Sequoia) правый клик → **Открыть** её больше не обходит; разрешите
один раз через **Системные настройки → Конфиденциальность и безопасность → Всё
равно открыть** (кнопка появляется после первой попытки запуска) или снимите
флаг загрузки из терминала:

```bash
xattr -dr com.apple.quarantine /Applications/CandiShelf.app
```

Полностью убрать проверку Gatekeeper можно только с платным Apple Developer ID и
нотаризацией.

### Как выпустить релиз

1. В [CHANGELOG.md](CHANGELOG.md) добавьте изменения релиза в новый
   раздел `## [x.y.z] - YYYY-MM-DD`.
2. Сделайте коммит, затем создайте и отправьте тэг:

   ```bash
   git tag v0.1.0
   git push origin v0.1.0
   ```

3. GitHub Actions соберёт все платформы, синхронизирует версию приложения с
   тэгом, сформирует описание релиза из раздела changelog для этой версии и
   опубликует релиз с контрольными суммами.

## Что намеренно вне MVP

Авторизация и аккаунты, multi-user, серверная версия, SSO и роли, email и
календарь, публикация вакансий, полный ATS-пайплайн, OCR сложных сканов,
автоматические обновления, интеграции с LinkedIn, резервное копирование в облако
и автоматический отбор кандидатов.
